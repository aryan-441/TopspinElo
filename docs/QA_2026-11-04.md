# Rallydesk project verification — 4 November 2026

## Decision

The local-preview foundation can support further development, but the complete product brief is **not finished or ready for public release**. Passing the checks below does not certify every combination of inputs, hardware, or future production feature. This report distinguishes executed tests from code review and missing scope.

Tests used isolated browser profiles and fictional demo records. The user's active browser workspace was not cleared or modified. The Python application and browser application have independent data models and stores; passing one does not establish behaviour in the other.

## Defect fixed during this audit

Backup restore previously accepted a profile with only an ID and name, and performed little nested validation. Such data could break player, scoring or tournament views after confirmation. Restore now validates key fields, numeric score maps, identity uniqueness, participant references, event shapes, referees, activity records and category/group structures before offering confirmation. Regression cases accompany the change. This remains application validation rather than a complete formal schema/migration system.

## Repeatable checks

From the repository root, run `python -m unittest -v` using a writable TEMP/TMP directory, `npm --prefix frontend test`, and `npm --prefix frontend run build`.

For browser checks, start Vite on 127.0.0.1:5173 and install/provide Playwright and browser binaries. Set `RALLYDESK_PLAYWRIGHT_PATH` to a Playwright module directory when it is not installed normally, and `RALLYDESK_BROWSER_EXECUTABLE` to the Chromium/Edge binary when using an existing browser. Run `npm --prefix frontend run test:browser`. The runner executes nine suites, saves results in `.test-tmp/browser-qa-results.json`, and returns a failing exit code for a failed suite. Screenshots and detailed outputs also stay in `.test-tmp`.

## Limits of this sign-off

Full physical-device, screen-reader, keyboard-only-every-form, team/doubles-browser-journey, adversarial security and real-world OCR benchmark passes remain outside the executed coverage. The team/doubles algorithms do have automated rule coverage. No claim of “every single feature is ready” is justified until missing requirements and these explicit gaps are resolved.
